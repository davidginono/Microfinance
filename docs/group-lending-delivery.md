Repeated contributions to one loan produce one payment for that loan. The envelope creates no additional journal, cash entry or receivable. ## Signed personal consent increment

- V94 retains the original checkbox events and adds immutable signature evidence tied to the participant, frozen policy and, where required, a delivered/consumed personal challenge. Earlier unsigned events are not backfilled as signatures. Future group funding requires every participant's signature evidence; existing funded loans and repayment history are unchanged. V94 has been applied to the disposable database and must not be rewritten.
- Signing uses the current saved personal signature and the current branch/account approval-OTP setting. It requires fresh own-loan UPDATE and guarantee APPROVE claims as well as scoped client access. Codes are specific to a participant/cycle and use the existing application OTP lifetime (ten minutes by default). They allow five failed attempts and at most four issues per ten minutes with a one-minute gap. Hashes are stored, not plaintext codes. Incorrect-code attempt accounting commits without recording acceptance; a successful signature, code consumption and audit event commit together.
- Code preparation commits before the configured email/SMS delivery call; delivery confirmation runs in another short transaction. The existing branch delivery service handles the channel and usage context. Undelivered codes cannot sign. English/Kiswahili forms show code and signature requirements, safe errors and permission-dependent actions.

## Shared guarantor capacity increment

- Ordinary and group guarantees now use one scoped commitment projection, counting a loan once even when both records exist. Current review stages and written-off obligations remain reserved; a pending top-up does not release its original guarantee. Unknown contractual liability or repayment history blocks required capacity assessment. A member retains a cycle commitment while another participant loan remains active.
- Ordinary approval locks the request, scoped loan and current guarantor capacity before rechecking product policy. Sorted group reservations use the same per-client lock, preventing concurrent group/ordinary approvals from consuming the same final slot. Invalid current profiles, foreign scope and closed loans cannot approve. No claims are granted and historical contracts are unchanged.
