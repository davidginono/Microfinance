# Integrated accounting ledger contract

The local general ledger is institution-owned. Journals retain a first-class branch dimension; account codes are unique inside the institution. Operational loan journals are immutable source evidence, not a second official GL.

## Tables owned by V43

- `accounting_account`: `id uuid`, `sacco_id varchar(255)`, `code varchar(40)`, `name varchar(160)`, `kind` (`ASSET`, `LIABILITY`, `EQUITY`, `INCOME`, `EXPENSE`), `normal_balance` (`DEBIT`, `CREDIT`), `parent_id uuid`, `usage` (`HEADING`, `POSTING`, `CONTROL`), `category varchar(40)`, `active boolean`, creator/recorded timestamp. No seeded accounts or policy defaults.
- `accounting_period`: `id uuid`, `sacco_id`, `starts_on date`, `ends_on date`, `state` (`OPEN`, `CLOSED`), creator/closing/reopening evidence and timestamps. Posting takes `FOR SHARE` on the period; closing must take `FOR UPDATE` on this same row. Periods may not overlap.
- `accounting_journal`: `id uuid`, `sacco_id`, `station_id`, `period_id uuid`, `effective_date date`, `recorded_at timestamptz`, `currency='TZS'`, `policy_id uuid`, `policy_version int`, `policy_hash varchar(64)`, `event_type varchar(40)`, `source_kind varchar(40)`, `source_reference varchar(120)`, `request_key uuid`, `payload_hash varchar(64)`, `description/evidence_reference`, `state` (`DRAFT`, `APPROVED`, `POSTED`, `REVERSED`), `maker_id/approved_by/posted_by uuid`, approval/post timestamps, `reverses_journal_id uuid`, `reversal_reason`. Source and request uniqueness is `(sacco_id,station_id,source_kind,source_reference)` and `(sacco_id,station_id,request_key)`.
- `accounting_journal_line`: `id uuid`, `journal_id uuid`, `sacco_id`, `account_id uuid`, `line_number int`, `debit numeric(18,2)`, `credit numeric(18,2)`, `memo varchar(240)`. Monetary precision is exact cents, at most 16 integral digits. Journal+line tenant composite foreign keys prevent foreign-account links. Lines are immutable from insertion. Posted/reversed journals both belong in accounting totals; linked reversal lines offset originals.
- `accounting_opening_batch`: reviewed opening provenance, end-of-date cutoff, optional journal link, kind `JOURNAL` or `ZERO_CERTIFICATE`, pinned policy, request/fingerprint, branch, maker/checker, review evidence. A genuine zero opening requires an explicit certificate with source evidence and independent reconciliation approval; it creates no balancing journal. Opening changes never fabricate loan transactions.
- `accounting_cutover`: one branch boundary with reviewed opening batch, effective cutoff, reviewer/evidence, `source_recorded_cutoff timestamptz` copied from the opening preview's recording time. Coverage includes current missing loan ledgers and unbridged vouchers; missing history never becomes zero.
- `accounting_audit_event`, `accounting_outbox`: immutable append-only state events and transactional delivery handoff.

## Public service

`com.sacco.mvp.accounting.ledger.service.AccountingLedgerService`

Services authorize claims and derive scope from `AppUserPrincipal`; request DTOs never include a tenant or branch. Account and journal reads are bounded.

`postSource(AppUserPrincipal actor, SourceJournalCommand command)` is `MANDATORY`: the owning source service must already hold its financial transaction. It requires an approved applicable LOCAL policy and enabled event, uses approved account mappings, validates scoped accounts/open period, and commits journal, audit, and outbox in that transaction. Commands retain immutable source IDs. It is never exposed as a generic HTTP endpoint. Manual journals cannot post control accounts. C must verify source records and use canonical source references; it must not accept client-selected event/source types.

All date-effective reporting uses journal `effective_date`; reproducing recorded-data cutoffs additionally filters `posted_at`. The minimum reporting inclusion is `state IN ('POSTED','REVERSED')`. Closing uses the shared period row lock; no table/global posting mutex.

The initial opening cutoff must equal the first approved policy's `openingDate`, even when it precedes policy `effectiveFrom`. Only that reviewed opening may use the opening exception; ordinary source events require the policy applicable on their date and must be strictly after the end-of-date cutoff. `openPeriod` requires an approved current policy. The narrow `openInitialPeriod(actor, startsOn, endsOn, openingCutoff, evidence)` bootstrap resolves the first approved LOCAL opening policy and requires its exact opening cutoff inside the period, including when the first policy starts in the future; it does not authorize ordinary historical postings.

`reverseSource(actor, originalJournalId, command)` also has `MANDATORY` propagation. The source workflow reverses its subledger in the same transaction, passes the actual correction voucher as source reference, `REVERSAL` as event, independent maker/checker, reason in description, and no user-supplied lines. The GL derives exact opposite lines and preserves both original and correction. Always use actual immutable `loan_journal_entries.voucher_id`; ordinary disbursement's baseline voucher is random, while repayment/reversal vouchers are transaction IDs. No assumed loan-application ID substitutes for the source voucher.

No institution policy, actual account code, historical opening amount, or human sign-off is supplied by software defaults. EXTERNAL authority is rejected locally and remains unavailable until an acknowledged outbox integration exists.

`sourceJournalId(actor, sourceKind, sourceReference)` has `MANDATORY` propagation and requires `ACCOUNTING_JOURNAL_REVERSE`. It resolves only the actor's institution and branch, rejects manual/opening identities, and requires the existing source journal to be POSTED or REVERSED. Missing and unposted sources are explicit errors. `sourceAccount(actor, code)` also has `MANDATORY` propagation, requires `ACCOUNTING_JOURNAL_POST`, and returns `LedgerDtos.AccountView` for the institution's actual active non-heading account under a shared row lock. Source workflows validate actual cash/bank/mobile-money category with this metadata; approved role mappings are separately enforced by `postSource` for the effective date.

The authoritative `coverage(actor)` requires a live reviewed opening: JOURNAL batch POSTED with its journal POSTED, or ZERO_CERTIFICATE batch APPROVED. Operational voucher rows are opening-covered only when their effective date is at or before the approved end-of-date cutoff **and** their posted timestamp is at or before `source_recorded_cutoff`. A later or late-recorded voucher instead requires a scoped GL journal with `source_kind='OPERATIONAL_CLEARING'`, `source_reference=loan_journal_entries.voucher_id::text`, and state POSTED or REVERSED. Late backdated sources remain visibly incomplete and cannot be silently replayed through the opening-only exception. Legacy loans in DISBURSED/PAR/DEFAULTED/PAID without an exact institution/branch `loan_ledgers` link keep coverage INCOMPLETE.

V43.1 replaces only the balance trigger function to dispatch journal versus line record fields with an explicit conditional. Applied V43 remains unchanged. Java supports PREPAYMENT (asset/debit) and EXPENSE_ACCRUAL (liability/credit) role/category validation; PREPAYMENT already exists in V43. EXPENSE_ACCRUAL database creation remains dependent on phase C's additive V44 category and guard extension.
