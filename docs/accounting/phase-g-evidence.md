## Source and approval boundaries

Draft previews read only scoped posted GL entries under one repeatable-read transaction, with an effective-period and recorded-data cutoff. Imported opening journals are included in opening balances and excluded from period movements. Missing reviewed opening coverage yields unavailable amounts, not inferred zeros. Finalization reads immutable independently reviewed closing evidence through `ReconciliationService.finalizedSnapshotForPublication`; no request-supplied amounts or proof flags are accepted.

Finalization retains the typed result, definition, mapping/checker evidence, calculation version, source close/checksum, current/comparison cutoffs and generated timestamp. Closed-period and approved-mapping locks remain held until the result commits. Reopening or retiring a mapping does not rewrite an archived result. New publication must use the latest approved closed source. Comparative evidence cannot have a recorded cutoff later than the current close; the current period must be reviewed again before using a newly reclosed comparison. A restatement links to the prior retained result and preserves both versions.

`verifiedResult`, `verifiedResultDigest`, `authorizeExport`, and the mandatory `verifiedVersionForPublication`/`verifiedResultForPublication` boundaries are provided to the H durable-artifact workstream. The latter validates the correct branch/institution source and exact retained hash/lineage while holding current source/mapping locks. `StatementMappingChangeListener` allows a repository-only H implementation to invalidate release evidence atomically without creating service cycles. H owns CSV/XLSX/PDF statement artifacts and final rendered/export verification.

Institution finalization requires fresh financial-view/institution and statement permissions, an active real staff member/institution/selected workspace, and the trusted D institution publication boundary. No fabricated branch principal or foreign registry query is used. The retained source contains canonical aggregate financial bytes and minimal branch close/version/reviewer/hash/cutoff lineage. `Result.dimension` is explicit; institution results have no branch close IDs. The issuing workspace remains an artifact ownership field. Period choices return only scoped closed-period IDs/dates with server pagination and a partial lookup index.

Every branch cutoff remains explicit. The top-level recorded cutoff is only the latest branch bound, not a shared snapshot cutoff. Comparative institution evidence must have its latest cutoff no later than the earliest current branch cutoff. Mandatory bilingual source/difference notes survive layout changes and export. Newly reviewed source allocations, reopened source periods, incomplete branch coverage and retired mappings block new publication. Archived aggregate bytes and result checksums remain readable under current institution authorization. Linked institution restatements preserve both immutable sources and results. The 29-component constructor and JSON without the seven new scope/lineage fields remain compatible branch artifacts.

## Cash flow dependency

New cash-flow saves, reviews and publications require calculation version 2. Archived version 1 definitions/results retain their original calculation and checksum; an old approved layout must be revised and independently reviewed before new publication. The tested transition preserves an archived 1.01 TZS result and rejects new version 1 publication.

Version 2 consumes D's frozen `automaticCashMovements` and full independently reviewed E `cashFlowAllocations` once each. Simple journals require exactly one ordinary approved activity placement. Repeated account placements require distinct operating/investing/financing activities and explicit independently reviewed exception evidence; allocation-only placements do not become an automatic classification fallback. Missing journal allocation IDs, mismatched activities, duplicate journal/version evidence and unbalanced splits fail publication. Internal transfers are validated, retain their evidence and contribute zero to cash totals. Decimal JSON reads retain exact monetary values.

An actual posted compound-journal test uses E maker/checker allocation, D close freezing, then G finalization: 1.00 TZS operating plus 0.01 TZS investing reconciles exactly to 1.01 TZS cash movement. Three mandatory activity totals, reconciliation rows, approved mapping exception notes and immutable allocation lineage remain visible when custom rows are hidden/collapsed. No institution policy or activity classification is inferred.

## Protected official formats

No regulator return is invented or seeded. An administrator-controlled deployment manifest is loaded only when an explicit local file path and matching SHA256 are configured (`app.accounting.regulatory-format-manifest`, `app.accounting.regulatory-format-sha256`). It must contain a primary official BoT/NBAA reference, applicability evidence, fixed version, prescribed period/deadline, fields, controlled calculations and permitted file format. Schema 2 additionally requires explicit BRANCH/INSTITUTION scope. Legacy schema 1 artifacts remain branch-scoped and cannot claim institution scope. A branch result cannot satisfy an institution-wide return. Institution routes cannot modify those artifacts. Approved institution layouts cannot replace protected official calculations.

The Bank of Tanzania's enacted Mainland Tier 2 regulations provide for periodic reports in a form and frequency specified by the Bank; they do not supply an institution's approved return artifact for this implementation. Primary source rechecked 2026-10-02: [Microfinance (Non-Deposit Taking Microfinance Service Providers) Regulations, 2019](https://www.bot.go.tz/Publications/Acts,%20Regulations,%20Circulars,%20Guidelines/Regulations/en/2020021122490967551.pdf). Actual format and jurisdiction approval remain external prerequisites.

Manual uploads retain actual bounded bytes with a server-generated checksum. CSV rejects executable formula cells and invalid UTF-8; XLSX rejects formulas, macros and external links; PDF rejects active actions and embedded content. These checks validate file safety/format. Independent reviewer evidence establishes that the manual file matches prescribed fields; the workflow records prepared/reviewed status and does not claim regulator delivery.
