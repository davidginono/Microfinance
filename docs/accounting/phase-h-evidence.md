## Durable operational execution increment

Prepared 2026-10-02 in the dedicated `accounting-h-verification` worktree, based on root `e2bcd93`. Implementation is under `reporting.execution`, with the existing operational report/template/export services as public dependencies. Migration V49 adds immutable requests, frozen typed result pages, owned logo bytes, and immutable artifacts. The current implementation captures published template/schema/dataset/metric versions, requester, institution/branch, effective period, recorded cutoff, actual PostgreSQL snapshot identifier, source coverage, totals, timestamps, checksums, independent acceptance evidence, and restatement links.

All generation pages share one outer `REPEATABLE_READ` transaction. Source reads take no financial posting locks. Result pages, requested artifacts, final state, and generation audit either commit together or roll back together. Artifact downloads read stored bytes and verify their checksums, without rerunning a template or refetching a logo. Screen pagination reads frozen rows and retains whole-result totals. Typed decimals are stored as decimal strings and reconstructed using the stable field catalog; they never pass through floating-point JSON parsing.

The queue has explicit finite limits: four active jobs per institution, two per requester, one running job per institution, three attempts, a three-minute worker lease, a 120-second transaction timeout, at most 20,000 result rows, 1,000 rows per stored page, an eight-MiB encoded-row budget, one MiB per page, 32 MiB per artifact, and 5,000 rows for PDF. Dispatch orders institutions by their previous start time and uses `SKIP LOCKED`; a brief queue-only advisory lock serializes cross-process claims. Export work shares the existing bounded export semaphore. These are implementation limits, not measured capacity claims. XLSX/PDF currently consume the finite assembled result through the existing exporter; heap measurement and integration load verification remain outstanding.

Fresh member, institution, branch, dataset, run, and export authorization applies at request, worker execution, each source batch, artifact generation, and download. Cancellation and permission checks use separate transactions so a long source snapshot cannot hide revocation or a cancellation request. Sharing does not grant access to result rows or artifacts. A guessed run or artifact ID cannot widen scope. The explicit `REPORT_RUN_APPROVE` and `REPORT_JOBS_REVIEW` claims have no default grants. Operational result acceptance never converts stated incomplete coverage into a complete financial statement or an audit opinion.
