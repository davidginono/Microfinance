# Reconciliation and period closing evidence

Scope: D01–D07, verified TZS, controlled CSV/manual evidence, institutional policies and verified opening balances still unavailable. No operational database was accessed and no institution approval was invented.

The dedicated worktree is `accounting-d-close/Microfinance`. Migration V45 adds approved statement-format registration, immutable statement imports/lines, reviewed match allocations and reversals, assigned exception reviews, dated source/control certificates, and immutable closing/reopening snapshots and decisions. V45.1 extends the database close guard to inactive branches with retained historical financial sources. No statement import writes a journal, loan receipt, or repayment allocation.

`ReconciliationService` owns authorization and transactions; its repository contains bound SQL and projections; the controller accepts authenticated scope and typed commands. `/finance/reconciliation` provides format/import/preview, scoped statement lines, posted candidates, reviewed splits/batches, matching reversal, exceptions, and balance certificates. `/finance/closing` provides checks, branch maker/checker reviews, institution completion, frozen snapshots, and controlled reopening. All visible labels are in both message bundles. Shared navigation is integrated by the coordinating agent.

Permissions are explicit with no default grants: `ACCOUNTING_RECONCILIATION_VIEW/CREATE/APPROVE`, `ACCOUNTING_CLOSING_VIEW/CREATE/APPROVE/REOPEN`, and separate `ACCOUNTING_CLOSING_INSTITUTION`. Every use case rechecks the current member, effective claims, active institution, active branch and branch access status. Platform administrators and client sessions cannot run financial use cases. Foreign branch/institution records are rejected. The institution-wide closing command returns no foreign branch registry and requires explicit institution permission.

Statement CSV V1 declares `date,reference,amount,kind` and signed cash-account direction. Imports require an independently approved format and active bank/mobile-money account, at most 2,000 rows/1 MB, dates within one year, exact TZS cents, nonzero movements, and opening plus signed movement equal to closing. Filename, original imported text checksum, evidence, account, date range, maker, recording timestamp and request payload hash are retained. Identical retries return the original import; changed retries or the same file/range under a new key are rejected. Duplicate rows remain visible. Deferred PostgreSQL constraints validate scope, balances and atomic line insertion; later line insertions and history edits/deletion are prohibited.

Matching only references posted lines of the same scoped account and direction. Account locking plus review-time capacity checks and deferred database capacity constraints prevent double allocation. Validation loads at most 100 allocation identifiers in set projections, locks relevant periods together, and batch-inserts allocations. Exact matching requires the same reference and full amount. Splits and batches are explicit proposals. Charges, settlements and reversals require explicit treatment. An independent decision activates allocations; independent linked match reversals release capacity while retaining the original evidence. Money and clearing accounts cannot be matched across different accounts, preventing a gross collection from being counted again as a channel settlement.

Unmatched, duplicate, partial, reversed, timing and channel-fee exceptions remain assigned with evidence. Independent review retains a reviewed difference; it never deletes the line or silently creates money. Source certificates retain source amount, posted debit-minus-credit amount and signed difference. Statement certificates must be supported by the imported closing balance. Loan certificates validate the approved principal mapping and historical local loan source; expanded source movements require the business-accounting source described below. Supplier/funding certificates require the public `BusinessReconciliationSource` owning-feature port as well as external evidence; an absent/unknown source blocks certification, including attempts to substitute a manual opening certificate. Cash counts and clearing balances retain controlled manual evidence and independent review.

Closing checks require reviewed openings, no unposted drafts, balanced postings, no unreviewed exceptions or untreated unmatched lines, dated non-stale certificates for money/control accounts (including inactive accounts with posted history), and no disbursed legacy loans without a ledger. Closing acquires prior/current accounting-period locks in date order; posting holds conflicting `FOR SHARE` locks. Reconciliation mutations also require open-period locks, including the complete statement date range and match corrections. Every active branch and inactive branch with historical journals, loan ledgers or statements must have a current independent review, then an explicitly authorized institution reviewer completes the period lock. Snapshot hashes are rechecked at approval and institution completion; changed source evidence requires a new version. Reopening requires a proposal, different reviewer, reason/evidence and separate permissions. Original snapshots and decisions remain immutable.

The public report API `finalizedSnapshot(actor, reviewId)` returns immutable ID, period, version, as-of date, recorded cutoff, checksum, stored JSON, reviewer, current `periodClosed`, `restatement`, and coverage. It preserves earlier approved versions after reopening; current publication eligibility additionally requires the latest approved branch close after the latest reopening. `finalizedSnapshotForPublication(actor, reviewId)` has mandatory transaction propagation and holds the period `FOR SHARE` through the caller's short final-result write transaction, preventing concurrent reopening from invalidating the checked state before publication commits.

Stored account rows include ID/code/type/normal balance/purpose, opening, period debits/credits and closing. Imported end-of-day `OPENING` journals are included in openings and excluded from period movements and cash-flow counterpart/transfer sources. Cash counterpart totals and multiple-money-account transfers are frozen separately. `cashTransfers.ambiguous_journals` and `noncash_pairs_possible` conservatively count money journals with multiple nonmoney legs, or multiple money legs plus nonmoney legs; report finalizers must reject these until an authoritative reviewed allocation source exists. Snapshot map keys are sorted before hashing for reproducibility across JVM restarts. Snapshot sources include the approved close-date policy, period policy and posted source policy versions, posted journal counts/totals/cutoff, statement checksums, reviewed certificates, matching review cutoff and retained difference evidence. `reviewedOpeningEvidence(actor)` and JSON `reviewedOpening` expose the exact coverage ID, journal ID, policy ID/version, canonical posting payload checksum, maker, independent reviewer, source/review evidence references, reconciled-through date and review/post times. The canonical payload hash is not misrepresented as an original-file checksum. Bounded snapshots reject more than 1,000 account/evidence rows rather than silently truncate.

`PeriodReopenListener.periodReopened(actor, period, reason)` is a public downstream invalidation port. Listeners run after scoped period locking and current institutional reopening authorization, inside the same transaction as the independent reopen decision. H can invalidate institution/period-wide release eligibility without returning cross-branch registry records. A listener failure rolls back both period state and decision; audit history remains preserved.
