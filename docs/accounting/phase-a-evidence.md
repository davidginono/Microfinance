Core validation: `mvn -q '-Dtest=AccountingPolicyServiceTest' test` passed 10 tests. The final focused run passed **20 tests, 0 failures, 0 errors, 0 skips**: 12 domain/unit, 4 MockMvc and 4 PostgreSQL tests. PostgreSQL 17.9 migration through V42 and Hibernate schema validation passed in the isolated `microfinance_accounting_a_test` database. PostgreSQL tests verify immutable/idempotent policies, institution separation, complete decisions, independent checking, competing-authority approval concurrency and transaction rollback on audit failure. Request tests verify CSRF, claims, malformed-input recovery, typed event-map binding and ignored scope/audit fields. Final domain regressions verify fresh platform-identity rejection and initial-policy opening coverage.

Reproduce using an isolated loopback database `microfinance_accounting_a_test` owned by `microfinance_test`, with `MICROFINANCE_POLICY_TEST_DATABASE_URL=jdbc:postgresql://127.0.0.1:55439/microfinance_accounting_a_test`, then run `mvn -q '-Dtest=AccountingPolicyServiceTest,AccountingPolicyControllerTest,AccountingPolicyPostgresTest' test`. The fixture never reads application datasource credentials or operational data. Without the opt-in environment variable, its four PostgreSQL tests are skipped rather than claimed verified.

`hasInstitutionHistory(String)` and `hasMemberHistory(UUID)` provide bounded internal lifecycle guards, including makers/checkers of rejected proposals. Administration integration must call them before deleting files/operational records and deactivate access when history exists.

No 1,000-RPS claim, production cutover, accountant approval or compliance certification is made. Rendered browser/mobile verification is coordinated by the root integrated H run; Java compilation and MockMvc forwarding alone do not prove JSP rendering.
