# Equity statement and Notes configuration

The 12 November 2026 instruction authorizes a component matrix, controlled movement types and institution-specific Notes. The reference image supplies a layout only; its funds, balances and percentages are not accounting policy.

## Staff workflow

The 19 November 2026 replacement removes the Statement setup bulk editor and its GET/POST `/reports/financial/statements/setup` handlers. Financial Reports now owns **Statement layout** at `/reports/financial/statements/layout` and the separate Equity movements workspace. Both require explicit FINANCIAL_REPORTS_VIEW and FINANCIAL_REPORTS_CONFIGURE claims. Institution layout is shared across its branches; journal classification remains limited to the staff member's current branch. Live assignment/claim checks still use GeneralLedgerService.requireActor. No permissions are added or granted.

Statement layout has two bounded resource sections: Equity groups and Notes. Add/Edit opens a focused page for one item, with searchable account checkboxes, inline errors, preserved failed submissions, optional Kiswahili fields and a bottom Cancel/Save action. Notes start with No figures; choosing Account balances or Period change reveals account selection. The group form chooses column position and optional untransferred profit. Notes keep their explicit number and optional equity-balance profit figure. Remove has a focused confirmation and reason. The obsolete repeated-row templates, comma-separated account-code parser, movement-label editor, request DTOs and their JavaScript/CSS are removed at source.

Each mutation appends an immutable institution revision containing the changed item and unchanged other groups/Notes. The service locks the institution, checks the submitted version and exact retry hash, validates the complete resulting layout, and records the real staff actor and reason. Record links carry the expected layout version because group/Note indexes are positions within an immutable revision; stale edit/removal links cannot silently target another item after a reorder. Unchanged edits create no revision or audit claim. Existing custom movement labels are read-only compatibility data, retained when other items change.

Equity groups accept equity posting accounts only. Accounts cannot overlap groups; Notes cannot overlap each other. A financial Note uses one account type and a closing-balance or period-movement basis. An equity closing-balance Note may explicitly include untransferred ledger profit, including as its only figure; this metric can belong to one Note only. Its amount comes from captured income/expense closing balances and its Note number also links the financial-position profit line. Text-only Notes have no accounts and require actual disclosure text. The accountant supplies policies and disclosures; no compliance declaration or reserve percentage is generated.

The shared `StatementSetupModels` snapshot records and `StatementSetupRepository` remain because current report capture, frozen reports and append-only history require their existing payload/table format. They expose no retired bulk editor. The old combined controller/service have been replaced by the focused layout and equity-movement owners. No database structure, account, journal, balance, saved report or stored artifact is changed by this replacement. New groups/Notes still require an explicit staff save; no configuration is invented during deployment.

The JSP implementation follows Cloudscape's [page edit](https://cloudscape.design/patterns/resource-management/edit/page-edit/), [single-page create](https://cloudscape.design/patterns/resource-management/create/single-page-create/) and [progressive disclosure](https://cloudscape.design/patterns/general/selection/) guidance using the existing ERP shell. Displayed configuration lists are complete and bounded by nine groups/thirty Notes; their logical order is the saved column order or Note number. Account search filters at most 2,000 institution-scoped posting-account choices. It never loads or filters a loan portfolio in the browser.

Approved COA equity-component labels remain the fallback for accounts without a configured override. Unclassified components remain explicit. The engine never omits their figures. A retained-profit component can combine its posted equity accounts with untransferred ledger profit; otherwise the latter has a separate column.

Equity movements lists posted journals with equity lines, scoped dates and fixed 30-row server pages. Staff select one journal, open Actions → Set movement type, then choose its type and save a reason in the shared dialog. The journal is posted first; Statement layout supplies group/account mappings and Notes, not automatic journal classifications. Types are capital added, owner distributions, reserve transfers, transfer of earned profit, other comprehensive income, other equity changes and unclassified. Stored custom labels retain the standard meaning in parentheses. Transfers between reserves require equity-only journals; transfers of earned profit require equity plus income/expense lines only. Capital additions, owner distributions and OCI cannot contain income/expense lines. Classification records do not amend journals or prove that an accounting policy is appropriate. Retrospective restatement is not inferred from an ordinary backdated journal.

## Ledger and history

Equity matrices and Notes were introduced in snapshot version 3; current captures use version 4. Current and comparative matrices separately show opening balance, profit/loss, individual movement types and closing balance. Every component reconciles independently. Transfers retain signed debit/credit effects; a reserve transfer increases one component and decreases another with no net equity increase. Configuration accounts missing from the captured chart stop generation instead of becoming zero figures. Missing classifications remain visible and produce review checks even when offsetting unknown transactions net to zero. There is no automatic distribution or posting.

Explicitly classified earned-profit closing journals are removed from period income/expense movements for profit reporting. Their amounts remain in the raw trial balance and ledger and move between equity components. This avoids erasing earned profit or counting it twice after closing. Movement-based income/expense Notes use the same exclusion. Balance-based Notes always use posted closing balances. Generating a report makes no monetary mutation.

Setup, classified movement aggregates, both matrices, Note membership/text and source journal membership are frozen in the same existing bounded repeatable-read capture. Saved version 1/2 snapshots and retained export bytes remain readable. Later setup edits, classifications or backdated postings require a new preview; saved reports never recalculate from them. Screen, PDF, print and Excel consume one typed document. Existing export claims and institution aggregation restrictions remain.

V158 adds only append-only setup/classification tables and scope/history protections. It does not change accounts, journals, balances, loan contracts, old statement payloads or seeded permissions. Apply deployment migrations with the project's verified-backup and clean-build procedures; no operational migration is run by this increment. Deployment must include pending lower-numbered migrations before V158; do not apply a cherry-picked V158 ahead of them.

## Boundaries and verification

There are at most nine configured components, ten final equity columns, thirty Notes, 2,000 posting accounts, seven movement categories and 32,000 grouped account/category/period movement results. Queries use scoped IDs, parameters, deterministic bounded pages and existing export admission control. Setup saves serialize by institution; classification saves serialize by institution/branch/journal. Expected revision and exact retry checks prevent lost updates. No executor, network integration, monetary lock, cache or posting path is added.

Reports retain the existing provisional recorded-ledger notice. This feature does not establish verified institution openings, complete disclosures, an approved reporting framework, final accounts or audited compliance. Configuration cannot remove reconciliation totals or review warnings. No throughput benchmark has been run; 1,000 requests/second remains unproven.
