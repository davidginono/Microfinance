# Access matrix and workspace tabs

The access editor uses one row per available feature/action claim, with Feature, Action, Claim and Allowed columns. The shared table search filters the bounded claim catalogue immediately by localized labels or the stored claim identifier. Unsupported combinations and retired claims are not rendered. Filtering never disables, removes or changes the named permission inputs; the original authorized POST form, CSRF token, role defaults and access checks remain intact.

The first checkbox selects a row for the shared read-only details pane. The Allowed checkbox edits the permission. Selecting or clearing a row never grants or revokes access. The existing split pane supports bottom/side placement, pointer dragging and keyboard resizing; its preview follows the selected claim and current edited state. Search and cached-page restoration clear selection. Restore default permissions still applies to the complete catalogue, including filtered-out rows, and saves only through the existing form command.

Shared resource detail tabs remember the active panel per pathname in browser-tab session storage. Explicit tab destinations and real validation errors take priority; missing or unavailable panels fall back to an existing panel. POST redirects and reloads preserve the selected panel without storing form values. Portfolio tabs follow the same presentation rule. Report-preview tabs already retain their selected kind in request/form context and keep their existing authenticated request lifecycle.
