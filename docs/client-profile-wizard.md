# Client profile wizard

3 November 2026: editable client profiles in the signed-in and OTP workspaces follow the [Cloudscape multipage-create pattern](https://cloudscape.design/patterns/resource-management/create/multi-page-create/) using four in-document steps: Personal details, Income and bank details, Documents and privacy, and Review and send. Review shows current values in step order, with Edit buttons returning to the original controls. Previous and Next do not submit requests. Save draft remains available throughout; Send for review appears on the review step. Submitted profiles retain the read-only view. Staff-assisted forms and public registration retain their existing layout.

Add document opens a native dialog within the live profile instead of navigating away. Users can choose several files, add more repeatedly, remove unuploaded files, and set each file's category and expiry. One privacy/accuracy confirmation appears below the complete selection; changing that selection clears the checks. These checks no longer appear at the end of the profile. Existing uploaded files can also be confirmed through the dialog. The actual selected acknowledgements remain in the profile form, and saved acknowledgements are restored only for the current standard notice. Server-side submission acknowledgement, identity/address/activity evidence, ownership, branch scope and assisted consent-evidence rules remain in force.

The dialog fetches the existing authorized document form and uploads each selected file through the existing multipart endpoint with its own request key, current revision and CSRF token. Successful uploads update only the document list. Pending files and the live profile survive a failed upload; successful rows are not replayed, and explicit retries retain the failed row's request key. There is no automatic submission or saving of the profile. Actual exits still use the shared unsaved-changes guard. Drafts must be saved before uploads, as before. The native single-file route remains available without JavaScript.

Multiple documents in the same category remain in the immutable upload history. Read views show the 100 most recent files received up to that version's last linked document, with a limit hint for older legacy records. Snapshot links, assessment and expiry checks retain their existing latest-evidence-per-category behavior, so a superseded expired document cannot change the KYC gate. No schema migration is needed.

New uploads allow JPEG/JPG and PNG images only, at most 1 MiB each. A client has a lifetime budget of 10 files and 10 MiB, counting prior uploads and historical branches within the institution after authorizing the client's current branch record. Existing legacy files remain unchanged and downloadable. The backend validates the filename, actual decoded image type, byte length and existing pixel limit; browser checks are supplementary. The budget is checked before storing and again under the existing client advisory lock. Rejected concurrent uploads roll back their metadata and local files through the storage service's existing rollback cleanup; idempotent retries return their recorded result even at the limit. Draft versions reuse existing file IDs and cannot reset the quota. The aggregate uses document/upload metadata rather than loading stored bytes.

The wizard moves existing controls without cloning them. It retains CSRF, request keys, entered values, conditional spouse/business behavior, income choices and existing draft/submission commands. Native field errors and document submission errors reveal the affected step. Session storage holds only a step identifier, never profile values or selected files. English/Kiswahili labels, a wrapping mobile step list and one-column mobile review facts use the shared JSP/CSS shell. The shared shell excludes wizard navigation from its icon-only pagination treatment. No threads or permission grants are added; no throughput claim is made.

Verification: 88 JavaScript interaction, validation, navigation and dirty-form checks passed; the final picker/wizard/conditional selection was rerun after the last UI fixes. Backend coverage comprises 25 PostgreSQL cases, 18 MVC/security cases, one architecture check, three JSPs in one Jasper compilation check, and one real HTTP/JSP/upload/submission/return/verification flow. The legacy-budget fixture was corrected to seed immutable old-limit files and passed its targeted rerun. Coverage includes exact/oversize image boundaries, filename/content mismatch, ten-file and total-byte limits, idempotent retries at the limit, competing uploads for one remaining slot, and retaining multiple same-category files after draft saves.

Browser checks used real rendered forms and synthetic actors: two selected PNGs uploaded without leaving the profile, preserving an unsaved address and avoiding the discard dialog. PDF, oversized-image and over-quota selections were rejected before upload. The dialog fit 360px and 1366px viewports without horizontal overflow, and closing restored focus to Add document. The fixture omits unrelated notification and profile-image endpoints. The owned PostgreSQL 18.3 database used loopback port 55681 and was stopped afterward. No production records were changed; no full-suite or throughput claim is made.
