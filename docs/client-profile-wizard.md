# Client profile wizard

3 November 2026: editable client profiles in the signed-in and OTP workspaces follow the [Cloudscape multipage-create pattern](https://cloudscape.design/patterns/resource-management/create/multi-page-create/) using four in-document steps: Personal details, Income and bank details, Documents and privacy, and Review and send. Review shows current values in step order, with Edit buttons returning to the original controls. Previous and Next do not submit requests. Save draft remains available throughout; Send for review appears on the review step. Submitted profiles retain the read-only view. Staff-assisted forms and public registration retain their existing layout.

The accuracy declaration belongs to Attachments and Documents; data-use consent stays with the privacy message. Document errors direct clients to upload the required files without asking self-service clients for separate privacy evidence. Server-side identity, address and activity evidence checks remain in force; assisted consent-evidence rules are unchanged. Drafts must be saved before separate uploads. Existing dirty-exit protection covers leaving the form or opening uploads with unsaved edits.

The wizard moves existing controls without cloning them. It retains CSRF, request keys, entered values, conditional spouse/business behavior, income choices and existing draft/submission commands. Native field errors and document submission errors reveal the affected step. Session storage holds only a step identifier, never profile values. Without JavaScript the complete native form remains usable. English/Kiswahili labels, a wrapping mobile step list and one-column mobile review facts use the shared JSP/CSS shell. The shared shell excludes wizard navigation from its icon-only pagination treatment. There are no new queries, transactions, threads or permission grants; no throughput claim is made.

Verification: 39 JavaScript interaction, validation, navigation and shared-shell checks; 18 onboarding MVC/security checks; three JSPs in one Jasper compilation check; and one real PostgreSQL/HTTP/JSP/upload/submission/return/verification flow, all passing. Browser checks exercised both income choices, review/Edit, required consent and draft save with step restoration. Review layouts fit 360, 768, 1366 and 1920 pixel viewports without horizontal document overflow; the document step was inspected in English and Kiswahili. The synthetic fixture omits notification and profile-image endpoints. Its owned PostgreSQL 18.3 database used loopback port 55681 and was stopped afterward. No production records were changed, and no full-suite or throughput result is claimed.
