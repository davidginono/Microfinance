# Phase F: operational report builder evidence

Software implementation only. Institution/accountant policy approval and verified opening balances remain absent and gated. These operational datasets do not authorize financial-statement release or certify compliance.

## Scope and architecture

The feature lives in `com.sacco.mvp.reporting.operational`, with page/API controllers, typed request/result DTOs, services, repositories and a template model. Controllers do not access persistence. It uses the existing JSP staff shell, local assets, session authentication and CSRF. Shared claims, navigation and EN/SW bundles are owned by the integration agent.

Sources are posted local repayments and linked reversals, verified local-ledger openings, immutable contractual instalment terms, and first-class institution/branch loan scope. No borrower snapshots, declared cash flow, future scheduled payment totals, or mutable paid counters establish posted financial balances. No GL or regulator dataset is offered.

## Security and query review

- Missing institution or branch fails closed; the service never widens to institution-wide records. Loan scope uses `LoanApplication.stationId`, not the client's current branch.
- Collections require `LOAN_REPAYMENTS_VIEW`; disbursements and portfolio require `LOAN_REPORTS_VIEW`, in addition to the requested template/run action claim. Permission-bearing client sessions and platform identities are denied.
- Columns are scalar operational values, not JPA entities. JSP text is escaped. Browser monetary JSON is string-valued and formatted through integer grouping, preserving cents beyond JavaScript's safe integer range.
- Untracked principal/interest remain null. Coverage includes missing-date disbursed loans separately; they cannot be assigned an invented reporting period. Collections coverage is all branch loans disbursed by the end date, explicitly distinct from the payment-date row filter. Disbursement coverage uses the selected disbursement window. Portfolio includes all loans disbursed by its as-of date, regardless of age.
- A preview performs a fixed three source queries (rows, filtered totals/count, coverage), plus one bounded group query if requested. Template pagination performs a content/count pair. No row-dependent database calls, network calls, spawned threads or mutable financial cache are introduced.
- `V47__operational_report_templates.sql` adds scoped date indexes, bounded config/state checks, unique version identity and immutability triggers. Representative index plans/capacity are unmeasured. Draft edits use optimistic locking; simultaneous clones cannot publish duplicate family/version identities because of database uniqueness.

## Integration contract

`OperationalReportService.run(actor, templateId, page, size)` runs only a published, visible template. `runAt(actor, templateId, page, size, cutoff)` rechecks the same scope for an export batch and uses append-only payment/reversal deltas through the cutoff. `preview(actor, definition, page, size)` and `parse(json)` use the same validator/catalog. `OperationalReportResult` carries immutable columns, BigDecimal/LocalDate scalar rows, whole-filter totals with available/unavailable row counts, bounded group totals, coverage including unknown dates, template/version/config/cutoff, institution/branch and configured-language labels. The browser-only `OperationalPreviewResponse` converts decimal cells/totals to exact strings.
