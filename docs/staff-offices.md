# Staff offices

**Loan reviews and archive.** Loan reviews show only items where the current staff member can approve or reject at the frozen workflow step. Disbursed Loans Archive counts distinct loans with a recorded decision by the signed-in staff member and confirmed unreversed funding in the current branch.

Institution staff have one personal `/staff/dashboard`. Each assigned group retains `/staff/offices/{office}/queue` and `/reports`. The fixed office slugs are `loan-officer`, `general-manager`, `finance-manager`, `chief-accountant`, `ict-manager`, `credit-officer`, `accounts-clerk`, `customer-care` and `accounts-clerk-2`. Super Administrator retains the separate platform workspace.

`StaffOffice` defines assignment and display order using `Position.staffAssignableRoles()`. Historical aliases normalize for presentation only. One Dashboard link appears above all assigned offices' Review queue and Reports links. Password, OTP and MFA use the same personal landing. Valid saved work destinations survive authentication; retired, unassigned and former role-dashboard destinations fall back to the personal dashboard. Former assigned-office dashboard URLs redirect after live assignment validation. Institution staff visiting `/admin/dashboard` also redirect to their personal dashboard; platform identities retain that route's platform view. Canonical endpoints still authorize every request.

Active staff with a current institution and branch can enter their office with an empty explicit permission set and incomplete optional profile details. They see **No work assigned** without business-data queries. Profile editing remains optional. Invitation activation, password/MFA requirements and action-specific evidence checks remain in force. Group membership grants no operation claims.

## Work and scope

The personal dashboard offers every authorized activity type across all assigned roles, once per type. Loan and voucher review widgets retain separate labeled counts and links for each assigned group; overlapping counts are never summed. Shared work is queried once and links to the first assigned office offering it. Existing administration widgets appear only with live `ADMIN_DASHBOARD_VIEW` access. Queues reuse existing feature services and detail/review routes, with server-side search, sorting and 25-row pages. A further row determines whether another page exists; `25+` means a bounded first-page count, not an exact total. Selection resets after navigation and filter changes. Validated office return context preserves the selected queue, search, sort and page through detail pages and command redirects.

`GET /api/dashboard/activities/{source}` returns only bounded counts for an allowlisted, currently authorized activity. It returns no loan/client records and cannot accept another institution, branch or office as its scope. Visible activity widgets use at most two simultaneous requests and refresh automatically five seconds after each response, with request cancellation and no manual Refresh button. Hidden widgets do not fetch. Initial loads use spinners; background updates retain the numbers on screen. A failed refresh retains earlier counts with an error and retries automatically; an authorization failure clears the counts and stops polling.

Personal layout storage uses stable staff identity, institution, branch and the personal dashboard, without a role component. This is a new layout namespace; former role layouts are not chosen as the personal default. Subsequent newly authorized widgets append automatically, retaining saved order, sizes and deliberately hidden widgets. Revoked widgets are absent from both board and picker. Storage contains only presentation preferences. Live assignment changes still require a valid updated session, and assignment alone grants no operation claims.

The Loan reviews card appears for staff with Loan View access whose group is in the branch's current configured approval plans or a pending frozen plan, including when their queue is empty. Staff with explicit approval/rejection claims retain their review card as well. Reading the queue requires scoped Loan View access and live group membership; actual Approve/Reject commands still require their explicit decision claims. The card does not grant those claims. Loan review projections use the latest round, frozen plan, current unfinished step and selected office group. They exclude the recorder, submitter, related borrowers and prior voters. Decisions continue through `LoanGroupApprovalService`, which rechecks eligibility and unchanged assessed terms. Voucher reviews use their frozen stage and existing independence rules; account-version reviews require an independent authorized reviewer. Own drafts, preparation work, waiting work and actionable reviews retain distinct states.

All reads enforce institution and branch scope in owning services. Live assignment changes invalidate an old principal; revoked claims disappear from office work. The support model has no first-class branch reference: its office queue uses the reporter's current institution and branch and excludes unassigned reporters. It does not expose institution-wide incidents. Queue reads are bounded and avoid per-row eligibility queries.

Office Reports links to permitted existing reports. Filters, cutoff dates, calculations, export restrictions and audit behavior remain owned by those reports. Empty report catalogues show an explicit empty state. Both clerk offices reuse the same accounting capabilities, subject to individually assigned claims. Client recording remains separate from independent verification.

No schema migration, permission backfill, financial transition, report calculation or borrower access is introduced. Deploy from a clean build so superseded dashboard code cannot survive in compiled output. Do not clean a running application's output directory.
