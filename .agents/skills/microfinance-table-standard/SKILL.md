# Microfinance Table Standard

## Permanent accounting register reference

Apply Cloudscape [table view](https://cloudscape.design/patterns/resource-management/view/table-view/) with [create](https://cloudscape.design/patterns/resource-management/create/) and [details](https://cloudscape.design/patterns/resource-management/details/) navigation. Receipt, payment and journal registers are separate full-width scoped resources. Use single-row checkbox selection, keyboard access, a live selected-record announcement, disabled View/PDF/Print until selection, and an always-independent Create action. Never add a row Actions column. Clear selection on filters, sorting, pagination and restored navigation; provide explicit empty/no-match states and pagination even on one page. Outputs are PDF/print, never CSV/Excel. Creation supports multiple transactions and direct accountant posting, not approval queues.

## Reusable console table component

Use `resource-table.js`, `resource-table.css` and the localized `fragments/resource-table-labels.jspf`, loaded by the shared header. This is the maintained JSP implementation of the [Cloudscape table view](https://cloudscape.design/patterns/resource-management/view/table-view/) and the compact AWS console reference supplied on 2026-10-13. Read these component files before changing table behavior; extend them instead of copying controls into each page.

- Opt a resource wrapper in with a stable `data-resource-table="workspace-resource"` key. The key also scopes local display preferences; never put client names, financial data or selection in storage.
- Title/count and compact actions occupy the first row. Use white neutral buttons for every action except an independent Add/Create action (`btn-launch`) at the end; Search and Edit are neutral too. Use a refresh icon at the start, 32px desktop action height, 2px corners and 6px action gaps. Wrap groups on mobile without stretching individual buttons. Selecting a row replaces disabled command placeholders with the actual commands; never display both.
- When the page title is repeated in the table, keep the table title/count and remove the standalone page title above it. Display the table with its existing commands, filters, paging and preferences; do not remove the table heading or column headings. Remove empty page-heading wrappers while retaining breadcrumbs, notices and independent controls. `resource-table.js` retires referenced (`data-table-title-id`) or matching page headings after creating the table header, preserving heading IDs/accessibility and marking the retained heading `data-workspace-title` for navigation focus. For authored registers, render the title only in the table header at its source. Keep distinct form/detail/dashboard titles.
- Filters occupy the left of the second row; borderless previous/current-page/next controls and a separated gear icon occupy the right. Always show pagination, including one-page and empty results. Only the inner table canvas scrolls horizontally; title, actions, filters, paginator and gear remain stationary.
- Use only the shared Cloudscape-style paginator: borderless SVG chevrons and the current page beside Preferences in the tools row. Never add boxed Previous/Next buttons, a "Page 1" footer, Unicode arrows or a second paginator. This applies to batch workspaces and inline receipt grids as well as registers. Keep the shared refresh icon, table tools and Preferences; protect editable/financial columns from hiding or reordering and omit unsupported sorting and page-size choices.
- JSON-backed editors opt in with `data-table-pagination-mode="external"` and use `ResourceTable.setPage(region,{page,hasNext,loading})`. Handle `resource-table:page` and `resource-table:refresh` in the editor controller, flushing drafts before requesting the next bounded server page. Reuse the shared pager renderer, icons, preferences and loading/disabled states; never replace editable rows using the HTML-register fetch adapter. External mode does not grant client-side pagination or bypass server scope checks.
- When no filter controls exist in that row, the component supplies a localized Search this page field. It searches only the bounded, already-authorized displayed rows, clears selection and shows a concise no-match state. Keep existing server filters/paging authoritative; use server search for whole-register queries and never load extra pages for this fallback.
- At laptop/desktop widths (1024px and above), keep filters, Apply/Clear and paginator/preferences in one non-wrapping row. Let filter fields shrink within available space, keep action buttons at their natural width, and align their bottoms with the inputs. Allow wrapping below this breakpoint for tablets and phones.
- Filter field wrappers use a column flex layout with a 20px label line, 4px gap and zero control margins. Inputs, dates, native/enhanced selectors and Apply/Clear are all 32px border-box controls. Remove inline-baseline space below select wrappers; changing only the outer toolbar alignment does not correct raised dropdowns.
- Empty lookup-error spans are hidden, so they do not create an extra flex gap below an enhanced selector and raise it above other inputs. Retain populated validation messages. Loading indicators never participate in local row filtering or appear alongside premature no-match states.
- Center single spanning empty/no-match cells in every ERP table. Sorting, pagination, Apply, page-size changes and Refresh use the shared cancellable GET request in `resource-table.js`; replace authorized server-rendered body rows and synchronize sort/pager state without reloading the document. Keep the original title/actions/filter nodes, preferences, selection controllers and scoped server queries. Retain old native rows while hidden behind a centered spanning spinner row inside the canvas, then replace on success or restore on failure. Clear selection, reject redirected authentication responses, ignore stale responses and end indicators in every completion path. Never attach a table spinner to page reloads/navigation.
- Add `data-table-pagination data-page="${records.page}" data-table-for="workspace-resource"` to the server-rendered pager. Page is zero-based. Mark controls `data-page-direction="previous"` or `"next"`; preserve their scoped server URLs and filter/sort parameters. Omitted controls become disabled chevrons. A shared server pager can name several table keys separated by spaces. Do not infer paging from translated labels or paginate only the loaded page in JavaScript.
- The gear opens a body-mounted, keyboard-accessible Preferences dialog with Confirm/Cancel. Display settings are page size on supported server registers, line wrapping, striped rows, compact rows, sticky first one/two columns, column visibility switches and ordering. Use a two-column preferences dialog; visibility/order on the right, other settings on the left. Column handles support drag and Up/Down keys. Confirm applies/persists display settings, Cancel discards them. Keep the identifying column and editable form columns available. Page-size choices are appropriate only when the server endpoint accepts and caps that size; do not add a cosmetic client-only page-size setting.
- For existing single-record controllers, add `data-table-selection="single"`. The leading header checkbox selects the first visible selectable row when empty and clears the selection when selected; its accessible label states that behavior. It never enables a bulk financial command. Use a mixed state when one of several rows is selected. Clear selection on filters, paging, confirmed preferences and restored navigation. Row selection itself remains owned by the page's existing permission-aware controller.
- For a legacy resource table with a final command column, mark its header `data-table-actions-header`. The component replaces that column with leading selection and moves the selected row's actual links/forms into the toolbar, retaining CSRF, targets, values and permission conditions. Unselected commands are disabled. Use this adapter for native commands; custom delegated handlers that depend on row ancestry require an explicit page controller. Do not apply it to an inline editor or account picker where cell controls are the task itself.
- Do not add selectors to financial summary tables that have no record commands. Do not apply interactive tools to PDF/print stationery. Keep helper explanations out of the toolbar; labels, empty/error states and required financial context remain.

The rollout includes accounting registers/configuration, loan recording/client ledgers, reconciliation, and the member, admin, manager, board, chairperson, disbursement, loan officer, staff analytics, support and repayment resource views. Opt each resource in explicitly; shared assets alone do not opt a table in. Dashboard summaries and inline editing/picker controls retain their own task behavior.

- Keep whole-report filters above report KPI cards in their original Report controls section; do not bind those filters to a lower breakdown table. Bind external GET filters, headings and independent actions with `data-table-filter-for`, `data-table-heading-for` and `data-table-toolbar-for` using the resource key. Move original POST forms as complete envelopes, never only their buttons or hidden CSRF fields. A `data-table-title-id` can reuse a page title when no section heading exists. Keep PDF/download forms independent of query filters.
- Mark every actual record-command header `data-table-actions-header`, including resources with separate Details and lifecycle columns. The adapter consolidates them into single-row selection and one Actions menu for all selected-record commands, preserves original controls/listeners and displays selected-row restriction notes. Hydrated replacement rows acquire the same contract; removing a selected row clears its commands. Row-dependent custom handlers must capture or explicitly bind their record context before commands move.
- Declare `data-table-page-size-options` only from an existing server-supported size set (staff registers use 25/50/100). Preserve a native `size` field without adding duplicate request parameters; the preferences dialog supplies its presentation. Fixed or unsupported endpoints have no page-size setting. All server pagers need explicit resource keys and zero-based current pages, including c:url-built links and multiple tables sharing a pager.

## AWS reference and split details

Follow the [observed finder workflow](../microfinance-ui-style/references/aws-instance-type-finder.md) for the exact reference, evidence limits, shared component mapping and responsive adaptations.

- Match the supplied classic AWS console references: local Amazon Ember, light `#f2f3f3` canvas, square white table containers, `#fafafa` title/tools/header surfaces, `#eaeded` row rules and short vertical header separators. Use compact 13px table values and bold grey headings; retain the density preference. Only Add/Create uses orange; every other action is white with a thin neutral outline. Keep 16px icons, search magnifier and italic placeholder. Use arrows only for real navigation or sortable columns. Use the shared Cloudscape 16px SVG geometry, not Unicode triangles or double arrows.
- The 2026-10-14 density correction uses `#fafafa` headers, bold 13px `#545b64` Amazon Ember labels, 18px leading and 12px horizontal padding. Body values use 13px text and 18px leading. Compact rows are the default (6px vertical padding); comfortable rows use 8px and remain a preference. Preserve explicit saved density choices. Keep short `#eaeded` header dividers, none in body cells, and a narrow selection column. Legacy `shell.css` declarations use `!important`; verify the rendered cascade in `resource-table.css` instead of copying page overrides.
- Do not stop at defining the arrow SVG: verify each register explicitly binds its supported heading to a server sort. A GET filter form can declare `data-table-sort-asc`/`data-table-sort-desc` on a heading using its actual accepted sort values (date: oldest/newest, amount: amount_asc/amount). For separate direction parameters, also declare `data-table-sort-key`. The shared adapter builds a scoped link from the current form, preserves filters/size, resets page zero, sets `aria-sort`, and clears selection. COA whitelists code/name/parent/type/kind/normalBalance/status and asc/desc before bounded SQL ordering, retaining the tenant and parent restrictions and ID tie-breaker. Expanded children retain ordering. Never attach pretend arrows to unsupported report or editor columns. Active headings and carets are dark; inactive carets are hollow gray and stay at the trailing edge.
- Sortable headings contain a real scoped server link marked `data-table-sort` and an `aria-sort` state on the `th`. The shared component places a hollow Cloudscape caret on the right when unsorted and a dark filled caret for the active sort, pointing up/down with direction. Every data column in a resource register must have a working ascending/descending sort. Add missing server ordering before LIMIT/OFFSET, using explicit whitelisted columns and stable ID ties; never substitute page-only sorting. Selection and command controls are not data columns and retain their existing controls. Activity registers whitelist code/name/status and asc/desc; Transaction registers also support activity code, accounting event and posting-template state. Core loan, disbursement, repayment and receipt/payment/journal registers support every displayed data column through the shared RegisterSort whitelist, order before bounded pagination with an ID tie-breaker, reset the page on a new sort, retain search/status/activity/size, and clear selection. Do not sort a loaded server page locally or add decorative sort pointers.
- For grouped record commands, mark each existing direct toolbar button/link/form `data-table-command`. The shared component moves the original nodes into an Actions menu with a filled downward caret, neutral rectangular outline, disabled state when every command is unavailable, keyboard navigation, Escape/outside dismissal and focus restoration. Preserve permission gates, CSRF, changing command labels and existing listeners; never clone financial forms. Order is Refresh, Actions, then orange Create. All selected-record toolbar commands belong in this one menu, including View/Open, history, PDF/download, Print, lifecycle and review commands. Mark every such button/link/form `data-table-command`; never leave a duplicate standalone command beside the menu. Keep independent Create/Add and refresh outside, and preserve native resource-ID links in rows. Apply the same rule to custom selection controllers and the legacy row-command adapter; do not classify navigation commands as a separate toolbar group.
- Actions uses the classic AWS hover/focus treatment: enabled options have dark readable text, a pale-blue fill and blue border/text when highlighted; disabled options remain muted and cannot activate. Keep the trigger click/keyboard operated. Exclude menu items/triggers from generic neutral-button overrides and verify the rendered cascade. Each existing controller owns its permission, selection, lifecycle and eligibility conditions; the shared menu must never enable all options merely because it opens. Skip disabled/hidden options during keyboard navigation, block native and ARIA-disabled commands before page handlers, and update the trigger when availability changes.
- Page-size support is explicitly declared by `data-table-page-size`. COA, Activity/Transaction and receipt/payment/journal registers accept 10/30/50 (legacy service callers retain 25), validate the size before querying and fetch only size+1 rows. Preserve size in filters/pagers and reset page to zero when changing it. Fixed financial reports and inline editors retain their bounded server layouts; do not silently paginate a loaded slice or show fake page-size options.
- Opt read-only selection workflows into `resource-split-view.js` with `data-resource-split`. Current examples: COA, Activity/Transaction registers and vouchers. The user's 2026-10-29 instruction requires the pane to start closed at every viewport width, on workspace loads and when returning from browser history. Only Show details opens it; row selection, saved position/size, refresh and viewport changes never open it automatically. Retain bottom by default, optional side placement, close/reopen and a pointer/keyboard resize separator, following [Cloudscape split view](https://cloudscape.design/patterns/resource-management/view/split-view/). The configured split size includes the header and divider; resizing exchanges space with the table without shifting the toolbar. An already open panel updates its facts when selection changes.
- Render only the selected authorized row's facts; never infer extra financial detail, query whole portfolios or duplicate financial actions in the pane. Existing View/details navigation remains authoritative. Selection reset clears the preview. Store only position/size, never record data. Use tabs only for actual distinct content; the basic preview uses a heading rather than a decorative single tab.
- Identifying and editable columns stay visible and keep their positions. Reordering must preserve original cell identity, form values, event listeners, selection-controller assumptions and dynamically inserted rows. Combined/summary cells retain their structure.
- Check preferences Cancel/Confirm, ordering by keyboard and drag, dynamic rows, sticky offsets after resizing, striped/compact/wrap combinations, page-size query limits, split close/reopen/reset, and mobile overflow. Browser validation must use the user's existing signed-in session.

## Shared Structure

Use the existing JSP table contract rather than introducing a React/Cloudscape adapter:

```jsp
<div class="erp-table-wrap" data-resource-table="loan-repayments">
    <%-- Title, record actions, and filters stay outside the scroll viewport. --%>
    <div class="erp-table-scroll" data-view-position-key="loan-repayments-table">
        <table class="erp-table">
            <!-- Table header and rows -->
        </table>
    </div>
    <%-- Server pager is promoted beside filters; it stays outside the scroll viewport. --%>
    <div data-table-pagination data-page="${records.page}" data-table-for="loan-repayments">
        <c:if test="${records.page > 0}"><a data-page-direction="previous" href="<c:out value='${previousUrl}' />"><spring:message code="common.previous" /></a></c:if>
        <c:if test="${records.hasNext}"><a data-page-direction="next" href="<c:out value='${nextUrl}' />"><spring:message code="common.next" /></a></c:if>
    </div>
</div>
```

- Reuse the definitions in `src/main/resources/static/css/shell.css` and the nearest established table on the same workspace.
- The outer wrapper owns the title, filters, record commands, and pagination. Only table rows and the sticky column header belong in the inner scroll viewport.
- Do not combine `erp-table-wrap` and `erp-table-scroll` on one new element. Avoid a second card around a standalone table.
- Keep shared sticky headers and bounded scrolling. Use `erp-table-scroll-sm` for compact embedded tables and `erp-table-scroll-lg` only when the task needs a taller list.
- Choose a stable, non-sensitive view-position key and preserve existing filter, pagination, and return context where the shared shell supports it.

## Loan And Financial Columns

- Use short concrete headers and client-facing identifiers: Loan ID, Client Number, Branch, Due Date, Payment Date, Reference, Principal, Interest, Fees, Amount, and Status as relevant.
- Workspace table headings and values share the left leading edge, including Debit, Credit and monetary columns, so values do not drift to the far edge of wide columns. Use consistent precision and tabular numerals. Explicit centered selection/utility columns may remain centered in both header and body. Standalone PDF/print stationery retains its financial layout. State `TZS` in a visible column heading or shared context; distinguish zero from unavailable data.
- In repayment tables, distinguish actual received payments, allocation components, unapplied amounts, reversals, and projected instalments. Do not mix a repayment schedule into transaction history without clear separation.
- Collections tables distinguish days past due, overdue amount, and outstanding principal; PAR is not the same as the sum of missed instalments.
- Keep identifying information and financial consequences visible on mobile. Let the inner viewport scroll horizontally instead of hiding essential amounts, statuses, or receipt actions.
- Allow names and descriptions to wrap. Reserve `whitespace-nowrap` for short identifiers, dates and amounts.

## Selection And Record Commands

- Resource IDs, reference numbers and primary codes are native blue hyperlinks to their existing authorized details destination. Use `resource-table-id-link` on the server-rendered anchor, retain escaped readable labels, and preserve the existing route/context and permission gate. Missing IDs or resources without an authorized details destination stay plain text. Apply this to admin Users and roles/Institution Registry, staff review queues/archives, and equivalent resource registers; document previews and inline pickers retain their own behavior.
- ID navigation is available directly, without requiring checkbox selection. Row-body selection must ignore the anchor and preserve native Tab/Enter, open-in-new-tab and modified clicks. Checkbox selection still controls toolbar commands. The no-row-command rule permits these ID hyperlinks; it continues to prohibit row action buttons and an Actions column. Do not substitute a link to a different operation, expose a forbidden edit route, or invent details routes.
- Do not add an Actions column or command buttons to table rows. Put every record-specific command in the compact table-header Actions dropdown, outside the row scroll viewport; View/Open, Download PDF and Print are menu options too. This applies to new and edited tables; do not migrate unrelated pages without a requested scope.
- Disable record commands until the required selection is present. For a single-record workflow, use one selected row with a leading, accessibly named checkbox: selecting another replaces selection, and clicking the selected checkbox or row body again clears it. Support native Tab/Space, a visible row highlight/focus indicator and a screen-reader-only selection announcement. Do not add a visible selection summary or Clear selection button.
- Bind navigation and lifecycle commands to the selected record, derive labels such as Deactivate/Reactivate from its state, and retain service-backed permission and eligibility restrictions. Keep CSRF on POST commands; UI selection is not authorization.
- Clear selection on filter changes, pagination and cached-page restoration so commands cannot target a stale record. Row-body selection must ignore links, buttons and form controls. Keep independent Create/Add New commands available without selection.
- Reuse existing accounting controllers in `accounting-accounts.js`, `accounting-library.js` and `accounting-vouchers.js`; the shared resource-table component supplies their header selector and preference/filter reset contract.

## Data And Interaction

- Use institution/branch-scoped server-side `Pageable`, projections, counts, and aggregates. Never load a complete portfolio into the browser to paginate or calculate totals.
- Preserve sort and filter parameters through pagination and exports. Use deterministic sorting with an ID tie-breaker; cap page sizes and validate filter input on the server.
- A displayed total must match the authorized filter scope and be computed from the financial source of truth. Do not sum only the current page and label it a portfolio total.
- Search, clear, loading, empty, error, and refresh states must be functional. Failed fetches retain the original rows and show a local Refresh retry for the failed query. Abort pending work on page exit, reject stale responses and clear the preview before replacing rows; never show stale selection commands or navigate the document to recover a table request. Keep table dimensions stable as data loads; show an empty-state row with the correct `colspan`.
- Distinguish an empty register from a filtered search with no matches. Give no-match states a short recovery instruction to change or clear filters. Keep a register's Add New action compact and top right in its titlebar.
- When navigating to a register from a parent row, preselect the parent in a visible filter and preserve it through search/pagination. Avoid repeating the selected parent as a separate page-body label when the filter already conveys it; the filter is context, not authorization.
- Keep exports and receipts subject to the same authorization as the list. Large reports should be batchable rather than unbounded synchronous downloads.

## Verification

Selected-row previews use the stable localized Details heading. Client/loan identifiers and combined ID/name labels belong in labeled values inside the pane, never its title; retain direct authorized ID links in the table.

Verify the running server uses the changed build before reporting completion. For packaged runs, inspect the active WAR path and check the served command markup against the source; an older WAR can keep serving standalone actions despite passing source tests. Rebuild/restart the local app when needed, and verify a fresh authenticated page as well as table refresh and restored navigation. The table Refresh control updates rows, not deployed JSPs or toolbar assets.

Check sticky headers, pagination, sorting, filter persistence, long labels, zero/missing amounts, empty/error states, selection toggling/replacement/reset, command targets/states, and branch/client isolation. Verify ID link targets, normal/visited blue styling, hover/focus visibility, keyboard/native modified clicks and permission-dependent plain-text fallbacks. Confirm ID navigation does not toggle selection and checkbox selection still enables the correct toolbar commands after a server refresh. Confirm there is no Actions column or row command button, and no standalone selected-record action beside the Actions dropdown. Check menu-only View/PDF/Print, keyboard access, disabled/no-selection and restricted states, record replacement, filter/page/refresh resets and native form/CSRF preservation. At mobile and desktop widths, confirm the page does not overflow and table tools remain outside the scrolling rows. Verify reversed transactions cannot be mistaken for new receipts or silently removed from history.
